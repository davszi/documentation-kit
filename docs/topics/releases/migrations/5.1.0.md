# Migrate to kit 5.1.0

This guide applies the [5.1.0 release notes](../releases.md#510--the-reference-section-lists-named-folders-only)
to an existing 5.0.0 consumer. Prepare the upgrade as in the
[1.1.0 guide](1.1.0.md#prepare-the-deliverable): record the old and new kit
commits, keep a baseline build and follow the project's permissions and staging
workflow.

A project on an older version follows the earlier guides first, oldest first,
for their content steps, and then this one. It moves its pin once, straight to
`v5.1.0`. In the [5.0.0 guide](5.0.0.md) it does the step below in place of
the section "Settle what the Reference section lists"; every other section of
that guide applies, with the tag `v5.1.0` wherever it writes `v5.0.0`. Its
opening warning then holds for the folders `reference_roots` lists, not for
every tracked Markdown file.

## Name the folders the Reference section lists

From 5.1.0 the Reference section lists the tracked Markdown files under
`docs/` and nothing else, unless `reference_roots` names more. The setting
`reference_exclude` is removed: a `site.toml` that names it fails the build.
[Automatic reference listing](../../../../rules/site/authoring.md#automatic-reference-listing)
has the full rule.

A file under a listed folder becomes a page of the site. A private repository
with a public site publishes it at the next publish. Do this step before a
commit with the moved pin is pushed to a branch whose push publishes the site.

1. Delete `reference_exclude` from `docs/site/site.toml`, in the commit that
   moves the pin. Under 5.0.0 the deletion alone lists every tracked Markdown
   file again. `reference_roots` is a new top-level key: a project that
   already used the name for its own value renames its key first, as in
   [Rename own keys with the new names](5.0.0.md#rename-own-keys-with-the-new-names).
2. Print where the project's tracked Markdown lies, from the project root:

   ```bash
   git -c core.quotePath=false ls-files -- '*.md' | grep -v '^\.' | awk -F/ '{print (NF > 1 ? $1 "/" : $0)}' | sort | uniq -c
   ```

3. Decide with the owner which of those folders and root files belong on the
   site. `docs/` is listed unless the project decides otherwise. For a private
   repository with a public site, the owner decides this folder by folder.
4. Write the decision above the first `[[nav]]` table. A set value replaces
   the default, so it names `docs` too:

   ```toml
   reference_roots = ["docs", "experiments", "README.md"]
   ```

   An entry is a folder or one Markdown file, written from the project root.
   It is a plain path, not a glob. Leave the setting out when `docs/` alone is
   right.
5. Keep single files off the site where needed. A file of a listed folder
   that must stay private goes into `private_prefixes` of the `[publication]`
   table. A file outside every entry that should have a page gets a
   `[[source_pages]]` table. `reference_listing = false` still lists only the
   `[[source_pages]]` tables.
6. After [moving the pin](#move-the-pin), and once the build passes, print the
   files that are listed automatically:

   ```bash
   python -c "import json; d = json.load(open('.build/docs/site-build.json')); print('\n'.join(sorted(s for r, s in d['source_pages'].items() if r.endswith('.md.html'))))"
   ```

   Run it with the project's documentation interpreter. Lint prints a `NOTE:`
   line for an entry that lists no file.
7. Compare the printed list with the decision. Change `reference_roots`,
   rebuild and repeat until the list holds only files the owner approved.

Done when the owner has approved the printed list, or `reference_listing =
false` is set. No check enforces this step.

## Move the pin

Follow [Move the pin](5.0.0.md#move-the-pin) in the 5.0.0 guide with the tag
`v5.1.0`.

## Offer the owner's global agent instructions

Optional. 5.1.0 ships `.docs-kit/examples/global-agent-context.md`;
[the README](../../../../README.md#optional-the-owners-global-agent-instructions)
says what it holds and how a person takes it.

1. The person who upgrades decides for their own machine: add, replace or
   neither. An agent asks and writes nothing to the global file without a
   yes.
2. To have agents offer it to everyone who works in the project, copy the
   section "Offer the kit owner's global instructions" from
   `.docs-kit/examples/starter/AGENTS.md.tmpl` into the project's `AGENTS.md`.
   The project's owner decides this.

## Land the upgrade

Run the [project conformance check](../../../../rules/conformance.md) and
report its findings. Then follow [Land the upgrade](5.0.0.md#land-the-upgrade)
in the 5.0.0 guide; push only after the
[Reference step](#name-the-folders-the-reference-section-lists) is done. A project that
comes from 4.0.0 lands the steps of both guides in one upgrade.
