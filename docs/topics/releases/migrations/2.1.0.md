# Migrate to kit 2.1.0

This guide applies the [2.1.0 release notes](../releases.md#210--repository-files-in-the-sidebar-and-topic-records)
to an existing 2.0.0 consumer. 2.1.0 is not tagged yet; until it is, the steps
apply to a pushed commit on the kit's `main` branch. Prepare the upgrade as in
the [1.1.0 guide](1.1.0.md#prepare-the-deliverable): record the old and new kit
commits, keep a baseline build and follow the project's permissions and staging
workflow.

2.1.0 is a minor release. It removes no command, configuration key, marker or
adapter signature, and lint without `--strict` passes as before. It adds one
lint warning and changes the sidebar, so the upgrade still needs the steps
below; [what a version number promises](../releases.md#what-a-version-number-promises)
explains why. After them, run the
[project conformance check](../../../../rules/conformance.md) and report its
findings.

## Topic records

Every topic now has a record. Lint warns about a topic page that has neither a
record nor a `page_only` declaration, and `--strict` fails on that warning.

1. Run `python .docs-kit/docsite.py lint --project .` and collect the warnings
   that say `page without a record`.
2. For each named topic, read its page. If the page states a rule,
   specification, method, result or limit, create
   `docs/topics/<topic>/<topic>.md` and move that exact content into it; the
   page then explains the record in its own words and links its sections.
3. If the page has nothing a record would hold, declare
   `page_only = "<reason>"` in its frontmatter. Which cases may stay page-only
   is not settled, so report each reason to the project owner.
4. Run `python .docs-kit/docsite.py lint --project . --strict`.

Follow [rendered pages are for people](../../../../rules/documentation.md#rendered-pages-are-for-people-records-stay-markdown).
Moving content out of a page follows the project's deletion and review gates.

## Agent router

Add this row to the project's agent router in `AGENTS.md`:

```markdown
| Upgrading the kit pin or taking over the repository | The new version's migration guide, then `.docs-kit/rules/conformance.md` |
```

## Sidebar mark

The ∿ mark is no longer shared. Without a setting, the sidebar shows the
initials of `title`.

1. To keep the old mark, add `brand_mark = "∿"` to `docs/site/site.toml`, above
   the first `[[nav]]` table.
2. To use the project's own mark, set up to three characters or a tracked SVG
   file drawn with `currentColor`, as in
   [authoring paths](../../../../rules/site/authoring.md#authoring-paths).

## Removed tooling modules

`tooling/number_ledger.py` and `tooling/verbatim_blocks.py` are removed. No
known consumer imported them.

1. Search the project for `number_ledger` and `verbatim_blocks` imports from
   `.docs-kit/tooling`.
2. If one exists, copy the module from the `v2.0.0` tag into the project's own
   checks and import it from there. The rule in
   [numbers and staleness](../../../../rules/writing/evidence.md#numbers-and-staleness)
   stays; the project owns its ledger format and checks.

## Starter home link

A project created with the 2.0.0 starter has a home page that links
`../project/PROJECT_CONTEXT.md`, which does not exist. Change the link in
`docs/topics/home/index.md` to `../PROJECT_CONTEXT.md`.

## Changes that need review, not edits

- Pages load shared assets as `assets/<file>?v=<hash>`, so every generated page
  differs from its 2.0.0 build in those URLs.
- Build-sheet flows stack vertically in a narrow card, and grids, checks and
  chapter headlines follow the card's width. Review build-sheet pages at wide
  and narrow widths, following
  [validation and review](../../../../rules/site/validation.md#validation-and-review).
- The reader drawer shows the project mark and name and no chapter counter;
  hiding the menu applies across the site.
- A **Reference** sidebar section appears only on a site with
  `[[source_pages]]` entries.
- When a record section changes, lint prints notes naming the pages that link
  to it. Notes never fail lint.

## Pages that explain changed guides

These kit guides changed since 2.0.0. Reread the project pages that link to
them, as the conformance check asks:

- [Documentation system](../../../../rules/documentation.md): topic records,
  why pages and records overlap, record-change notes.
- [Site authoring](../../../../rules/site/authoring.md): `brand_mark`, pinned
  source pages, the Reference section, the removed ledger paragraph.
- [Validation](../../../../rules/site/validation.md): every visual change is
  reviewed by eye from whole-element captures.
- [Git](../../../../rules/engineering/git.md): the pin check counts remote
  branches only, not tags.
- [Evidence](../../../../rules/writing/evidence.md): the project owns its
  ledger format and checks.
- [Conformance check](../../../../rules/conformance.md): new guide.
