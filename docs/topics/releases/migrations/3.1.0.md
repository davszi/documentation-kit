# Migrate to kit 3.1.0

This guide applies the [3.1.0 release notes](../releases.md#310--one-site-name-in-the-sidebar-header-two-lint-warnings-relaxed)
to an existing 3.0.0 consumer. Prepare the upgrade as in the
[1.1.0 guide](1.1.0.md#prepare-the-deliverable): record the old and new kit
commits, keep a baseline build and follow the project's permissions and staging
workflow.

3.1.0 is a minor release. The name in the sidebar header can need an edit, and
a project that upgraded before 3.1.0 checks two instructions that earlier
guides gained. The lint changes need no edit. After the steps below, run the
[project conformance check](../../../../rules/conformance.md) and report its
findings.

## The name in the sidebar header

The sidebar header now shows one name on every page: `home_label` from
`docs/site/site.toml`, or `title` when `home_label` is not set or blank. In
3.0.0 it showed each page's `brand` frontmatter. Up to 2.0.0 a page with the
chapter reader already showed `home_label` in its drawer, so 3.1.0 restores
that name and applies it to pages without the reader and to registered source
pages as well. `brand` is deprecated: still accepted, without effect and
without a per-page replacement.

1. Read `title` and `home_label` in `docs/site/site.toml`. The header shows
   `home_label` if the file sets it.
2. If that is not the name the project wants on every page, change
   `home_label`, or delete it so that the header shows `title`. A label chosen
   for the reader drawer, such as "Research overview", now also heads the home
   page. The browser stores a reader's open navigation groups and pinned
   drawer under this name, so changing it resets those two preferences once.
3. Rebuild and look at the sidebar header on the home page and on one chapter
   page, wide and narrow.
4. Optional: remove the `brand` lines from page frontmatter. They have no
   effect.

A one-character `brand_mark`, such as `∿`, is drawn larger than before. Look at
it in the same captures.

## Lint

Two warnings are gone, so a project may now pass `lint --strict` where it did
not:

- A link to a file listed under `omitted_files` in the local-artifact manifest
  gets a note when the file is absent.
- A worklog entry without a commit hash is no longer reported.

No edit is needed. A project that runs lint without `--strict` only because of
these warnings can turn `--strict` on, in its checks and in its hosted
workflow.

## Instructions added to earlier guides

Two earlier guides gained an instruction. A project that upgraded before
3.1.0 checks both:

- [Experiment guides](2.0.0.md#experiment-guides) in the 2.0.0 guide: the
  router rows for the two experiment guides, and a row-by-row comparison with
  the starter router.
- [Router anchors](3.0.0.md#router-anchors) in the 3.0.0 guide: a link about
  the experiment floor goes to `rules/experiments/workflow.md#required-content`.

## Land the upgrade

Commit the moved pin together with the adaptations above, record the old and
new kit commits and the checks in the project's worklog, and report the
conformance findings. [Pin and upgrade](../../../../README.md#pin-and-upgrade)
has the commands.
