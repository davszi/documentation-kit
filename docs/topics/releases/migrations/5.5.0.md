# Migrate to kit 5.5.0

This guide applies the [5.5.0 release notes](../releases.md#550--text-of-11-px-or-more-lint-for-records-outside-docs-a-warning-for-a-repeated-id)
to an existing consumer on 5.2.0 to 5.4.1; those releases need no step of
their own. Prepare the upgrade as in the
[1.1.0 guide](1.1.0.md#prepare-the-deliverable): record the old and new kit
commits, keep a baseline build and follow the project's permissions and staging
workflow.

A project on an older version follows the earlier guides first, oldest first,
for their content steps, and then this one. It moves its pin once, straight to
`v5.5.0`.

## Move the pin

Follow [Move the pin](5.0.0.md#move-the-pin) in the 5.0.0 guide with the tag
`v5.5.0`. `requirements.txt` is unchanged.

## Give each repeated id one element

Strict lint now warns when a built page carries an id more than once; the
warning names the page and the ids.

- A heading whose id the page shell also uses, such as `top`, `menu`,
  `sidebar`, `toc`, `backdrop` or `chapter-reader`: with the tag `v5.5.2` or
  later the build numbers it, `menu-1`, and nothing is left to do. Links to
  the old id reached the shell, not the heading, so no working link changes.
- An id written twice in raw HTML, or a `{#id}` that names a taken id: rename
  one, and the links meant for it.
- A fragment included twice, or two inline drawings that share the id of a
  marker or gradient: give each copy its own ids, for example with a prefix.

Done when strict lint passes.

## Look at the small labels

The theme's labels below 11 px are 11 px now, 0.4 to 2 px larger, and inline
code in small text stops at 11 px. Capture the pages at a wide and a phone
width and look for a label that wraps or sticks out. A rule of the project
that sets one of these sizes still wins. Delete a workaround that raised
them. Done when the review by eye finds nothing; no check enforces this step.

A project that wants the limit checked on its own text calls `assertTextSize`
from the [reusable browser checks](../../../../rules/site/validation.md#reusable-browser-checks).
This is optional.

## Optional: name the records outside `docs/`

A project that keeps records outside `docs/` sets `record_roots`, as
[records outside `docs/`](../../../../rules/site/authoring.md#records-outside-docs)
describe. Lint then reads them, and what it never checked becomes an error: a
dead link or anchor, a snippet that left its source, an image from a
`figures/` folder without a `manifest.json` beside it, and a record that is
not UTF-8 text. Fix each, or leave a folder out with `record_roots_exclude`.
Done when strict lint passes.

## Land the upgrade

Run the [project conformance check](../../../../rules/conformance.md) and
report its findings. Then follow [Land the upgrade](5.0.0.md#land-the-upgrade)
in the 5.0.0 guide.
