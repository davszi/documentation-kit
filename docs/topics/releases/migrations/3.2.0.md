# Migrate to kit 3.2.0

This guide applies the [3.2.0 release notes](../releases.md#320--topic-group-folders-and-folded-navigation-groups)
to an existing 3.1.0 consumer. Prepare the upgrade as in the
[1.1.0 guide](1.1.0.md#prepare-the-deliverable): record the old and new kit
commits, keep a baseline build and follow the project's permissions and staging
workflow.

3.2.0 is a minor release. It adds two optional settings, and a project that
uses neither needs no edit: its pages, addresses and sidebar stay as they were.
After the steps below, run the
[project conformance check](../../../../rules/conformance.md) and report its
findings.

## Without the new settings

1. Move the pin, rebuild and run lint.
2. Read the lint output for a note that says `page is not built; add "<folder>" to topic_group_folders`.
   It names an `index.md` with page frontmatter two levels below
   `docs/topics/`, in a folder that has no page of its own. Earlier versions
   skipped such a file silently, and 3.2.0 still does not build it. Either
   name the folder as a group folder, as the next section describes, or leave
   the file as it is; the note never fails lint.

## Optional: move topics into a group folder

[Topic group folders](../../../../rules/site/authoring.md#topic-group-folders)
describes the setting. Move the pin first: a kit before 3.2.0 does not build a
page inside a group folder.

1. Add `topic_group_folders = ["<group>"]` to `docs/site/site.toml`, above the
   first `[[nav]]` table.
2. Move each topic folder with `git mv docs/topics/<topic> docs/topics/<group>/<topic>`.
   Keep the folder's name, so the page keeps its address `<topic>.html` and no
   link from outside the project breaks.
3. In the page body above `<!-- page-end -->`, links resolve from the built
   page. Leave links to other pages and to shared figures as they are. Change
   each link into the moved folder itself: `../topics/<topic>/<file>` becomes
   `../topics/<group>/<topic>/<file>`.
4. In the moved folder's records, and in notes below `<!-- page-end -->`, add
   one `../` to every relative link that leaves the folder. In other files,
   such as `docs/open/OPEN.md` and other topics' records, correct the links
   that point into the moved folder. Lint reports each link that is still
   wrong as a dead link.
5. In `docs/site/site.toml` and page frontmatter, correct the paths that name
   the folder: a `[[source_pages]]` `source`, an `[extra_assets]` source, and
   a `page_css` entry such as `<topic>/page.css`, which resolves from
   `docs/topics/`. The build rejects each one that is missing.
6. A frozen file keeps its bytes. Where the project lists it in a location
   map or evidence manifest, update the recorded path there first, as the
   project's own preservation rules say. Do this before any bulk edit of the
   moved folder, and leave each listed file out of that edit by its new path:
   a search and replace over the folder otherwise rewrites the frozen file.
7. Search the project's own code and tests for `docs/topics/<topic>`, for code
   that lists `docs/topics/*/`, and for code that checks the shape or depth of
   a topic path, such as a validator that accepts only
   `docs/topics/<topic>/evidence/<file>`. The kit cannot see these.
8. Rebuild, run lint and compare the list of built pages with the baseline
   build. It is the same list when every moved folder kept its name. A folder
   renamed on purpose changes its page's address; that is a separate decision
   under [refactoring over compatibility](../../../../rules/engineering/code.md#refactoring-over-compatibility),
   and the project updates or redirects the old address by its own rules.

## Optional: fold a navigation group

1. Add `folded_groups = ["<group>"]` to `docs/site/site.toml`, above the first
   `[[nav]]` table. Each name is the `group` of a visible `[[nav]]` entry, not
   a folder name. Keep the group's `[[nav]]` entries together; the build
   rejects a folded group that other entries split.
2. Rebuild and look at the sidebar wide and narrow: on a page outside the
   group, where it is closed, and on a page inside it, where it is open.

A project with its own stylesheet or tests for the sidebar checks them against
the folded group's markup: `details.nav-section.nav-section-fold` with a
`summary.nav-group`, where the other groups keep `div.nav-section` and
`span.nav-group`.

## Land the upgrade

Commit the moved pin together with the adaptations above, record the old and
new kit commits and the checks in the project's worklog, and report the
conformance findings. [Pin and upgrade](../../../../README.md#pin-and-upgrade)
has the commands.
