# Migrate to kit 3.0.0

This guide applies the [3.0.0 release notes](../releases.md#300--router-anchors-removed-topic-records-and-repository-files-in-the-sidebar)
to an existing 2.0.0 consumer. Prepare the upgrade as in
the [1.1.0 guide](1.1.0.md#prepare-the-deliverable): record the old and new kit
commits, keep a baseline build and follow the project's permissions and staging
workflow.

3.0.0 is a major release for one reason: it removes section anchors under
`rules/`, which are part of the stable interface, so links break.
`rules/writing.md` and `rules/maintenance.md` lose their section anchors,
sections move out of `rules/documentation.md` and
`rules/writing/explanations.md` into the new `rules/records.md` and the site
guides, and `rules/writing/evidence.md` is removed. Lint fails on a Markdown
link to an old location until it is repointed. Lint does not check links
written as HTML `<a href>`, so the searches below matter: correct every hit. No
command, configuration key, marker or adapter signature is removed. The release also adds one lint warning
and changes the sidebar; [what a version number promises](../releases.md#what-a-version-number-promises)
explains the rule. After the steps below, run the
[project conformance check](../../../../rules/conformance.md) and report its
findings.

## Router anchors

`rules/writing.md` and `rules/maintenance.md` are now plain indexes of the
focused guides. Their stub headings, which only forwarded older links, are gone.
A link to either file without an anchor still works.

Find the affected links:

```bash
grep -rnE 'rules/(writing|maintenance)\.md#' --include='*.md' --exclude-dir=.docs-kit --exclude-dir=.build .
```

Point each link at the focused guide named in the tables below. The anchor
itself keeps its name. In an append-only worklog, change only the link target
and leave the entry's wording as it is.

Do not rewrite a frozen or exact-evidence copy. If lint reports a removed
anchor inside one, report it to the project owner under the
[frozen-record rules](../../../../rules/records.md#evidence-identity-and-frozen-records).

Routers and prose may also name a section in bold without a link, such as
`**Numbers and staleness** in .docs-kit/rules/writing.md`. Lint does not check
those, and the search above does not find them. List every mention of the
affected files, including configuration and HTML fragments, and correct the
ones that name a moved section:

```bash
grep -rnE 'rules/(writing|maintenance|documentation)\.md|rules/writing/(evidence|explanations)\.md' --include='*.md' --include='*.toml' --include='*.html' --exclude-dir=.docs-kit --exclude-dir=.build .
```

| Former anchor in `rules/writing.md` | Guide that owns the section |
|---|---|
| `#page-design`, `#project-owned-homepages`, `#build-sheet-pages`, `#slide-faces`, `#completion-and-review` | `rules/writing/pages.md` |
| `#story-and-reading-layers` | `rules/writing/explanations.md` |
| `#naming-and-honest-claims` | `rules/records.md` |
| `#numbers-and-staleness` | `rules/records.md` |
| `#run-visuals-and-experiment-lifecycle` | `rules/writing/figures.md` |
| `#figures-and-comparisons`, `#interaction-and-access` | `rules/writing/figures.md` |
| `#mathematical-explanation` | `rules/writing/math.md` |
| `#code-and-diagrams` | `rules/writing/code.md` |

| Former anchor in `rules/maintenance.md` | Guide that owns the section |
|---|---|
| `#tooling-and-ownership`, `#authoring-paths`, `#generated-figures`, `#slide-faces-and-decks` | `rules/site/authoring.md` |

One of these anchors covered two subjects. In kit 1.1.0 the section behind
`#run-visuals-and-experiment-lifecycle` also held the experiment floor:
reproduction command, baseline, acceptance bar and regression gate. The figures
guide keeps the run visuals. Point a link whose sentence is about the
experiment floor at `rules/experiments/workflow.md#required-content` instead,
and one about regression gates at
`rules/experiments/verification.md#maintain-regression-gates`. Lint cannot tell
these subjects apart, so read each sentence that uses this anchor.

Then rebuild and lint: `python .docs-kit/docsite.py build --project .`, then
`python .docs-kit/docsite.py lint --project .`. Lint reports every Markdown
link whose anchor still does not resolve. It does not check HTML `<a href>`
links, so correct those from the search results.

## Sections that moved

Record rules now have their own guide, `rules/records.md`, so that an agent
writing a record does not read the page-design rules. The rules about what a
code excerpt, a formula or an experiment visual may claim still apply to
records; `rules/records.md` names them. `rules/writing/evidence.md`
is gone; its sections moved. Repoint links to these sections as well:

| Former location | Now |
|---|---|

| `rules/writing/evidence.md#run-visuals-and-experiment-lifecycle` | `rules/writing/figures.md#run-visuals-and-experiment-lifecycle` for run visuals; `rules/experiments/workflow.md#required-content` for the experiment floor; `rules/experiments/verification.md#maintain-regression-gates` for regression gates |

| Title anchor `rules/writing.md#writing-and-visual-evidence` | `rules/writing.md`, now titled "Writing pages for people" |

```bash
grep -rnE 'rules/(writing/evidence\.md|writing/explanations\.md#(naming|explanations-and)|documentation\.md#(evidence-identity|shelved|review-build))' --include='*.md' --exclude-dir=.docs-kit --exclude-dir=.build .
```

## Topic records

Every topic now has a record. Lint warns about a topic page that has neither a
record nor a `page_only` declaration, and `--strict` fails on that warning.

Taking content off a page is a deletion. Get the project owner's approval for
it before step 2, under the project's deletion and review gates.

1. Run `python .docs-kit/docsite.py lint --project .` and collect the warnings
   that say `page without a record`.
2. For each named topic, read its page. If the page states a rule,
   specification, method, result or limit, create
   `docs/topics/<topic>/<topic>.md` and state each of them there in plain
   Markdown, keeping the exact wording of rules and the exact numbers but none
   of the page's layout HTML. The upgrading agent writes this record itself.
3. Make the page explain the record and link its sections. A sentence or two is
   a small sync for the same agent; a larger rewrite is page work under
   [record first, page on request](../../../../rules/documentation.md#record-first-page-on-request).
4. If the page has nothing a record would hold, declare
   `page_only = "<reason>"` in its frontmatter. Which cases may stay page-only
   is not settled, so report each reason to the project owner.
5. Rebuild, then run `python .docs-kit/docsite.py lint --project . --strict`.

Follow [rendered pages are for people](../../../../rules/documentation.md#rendered-pages-are-for-people-records-stay-markdown)
and [writing records](../../../../rules/records.md).

## Agent router

Documentation is now routed by what is written. The agent that did the work
writes the record first. A new page for people is made only when a person asked
for one; an existing page is kept in step with its record, by the record's
editor for a small sync and otherwise by a separate agent where the runtime
supports delegation. See
[record first, page on request](../../../../rules/documentation.md#record-first-page-on-request).

In the project's `AGENTS.md`, replace the documentation row and the writing row
with the first three rows below. Add the fourth anywhere in the table; the
starter places it after the Git row.

```markdown
| Writing or changing a record: a guide, topic record, plan, worklog or open-work entry | `.docs-kit/rules/records.md`, and in `.docs-kit/rules/documentation.md` the sections from **Record first, page on request** through **Rules for changes and chronology** |
| Creating, moving, splitting or retiring a document | `.docs-kit/rules/documentation.md` |
| Making a new page for people, only when a person asked for one, or page work on an existing page beyond a small sync | **Record first, page on request** and **Rendered pages are for people** in `.docs-kit/rules/documentation.md`; the page author reads the applicable focused guides linked from `.docs-kit/rules/writing.md` and `.docs-kit/rules/maintenance.md` |
| Upgrading the kit pin or taking over the repository | The new version's migration guide, `.docs-kit/docs/topics/releases/migrations/<version>.md`, then `.docs-kit/rules/conformance.md` |
```

## Reading index

A project created from the starter has a `docs/index.md` table with the row
"Writing explanations, evidence and figures". Replace that row and the
"Documentation placement and lifecycle" row with these three:

```markdown
| Writing or changing a record | `rules/records.md` |
| Documentation placement, order of work and lifecycle | `rules/documentation.md` |
| A page for people: new on request, existing kept in step | Focused guides linked from `rules/writing.md` and `rules/maintenance.md` |
```

## Sidebar mark

The ∿ mark is no longer shared. Without a setting, the sidebar shows the
initials of `title`.

1. To keep the old mark, add `brand_mark = "∿"` to `docs/site/site.toml`, above
   the first `[[nav]]` table.
2. To use the project's own mark, set up to three characters or a tracked SVG
   file drawn with `currentColor`, as in
   [authoring paths](../../../../rules/site/authoring.md#authoring-paths).

## Removed tooling modules

`tooling/number_ledger.py` and `tooling/verbatim_blocks.py` are removed. No
known consumer imported them.

1. Search the project for `number_ledger` and `verbatim_blocks` imports from
   `.docs-kit/tooling`.
2. If one exists, copy the module from the `v2.0.0` tag into the project's own
   checks and import it from there. The rule in
   [numbers and staleness](../../../../rules/records.md#numbers-and-staleness)
   stays; the project owns its ledger format and checks.

## Starter home link

A project created with the 2.0.0 starter has a home page that links
`../project/PROJECT_CONTEXT.md`, which does not exist. Change the link in
`docs/topics/home/index.md` to `../PROJECT_CONTEXT.md`.

## Changes that need review, not edits

- Pages load shared assets as `assets/<file>?v=<hash>`, so every generated page
  differs from its 2.0.0 build in those URLs.
- Every built site gains `html/assets/documentation-kit/LICENSE`, the kit's
  MIT License. A project that compares or publishes its generated file list
  adds that file.
- A paragraph that follows a fold now renders as Markdown, with or without a
  blank line after the closing marker; it used to appear as raw text. Compare
  such pages with their 2.0.0 build.
- Build-sheet flows stack vertically in a narrow card, and grids, checks and
  chapter headlines follow the card's width. Review build-sheet pages at wide
  and narrow widths, following
  [validation and review](../../../../rules/site/validation.md#validation-and-review).
- The reader drawer shows the project mark and name and no chapter counter;
  hiding the menu applies across the site.
- A **Reference** sidebar section appears only on a site with
  `[[source_pages]]` entries.
- When a record section changes, lint prints notes naming the pages that link
  to it. Notes never fail lint.
- Optional: `page_number_notes = true` in `docs/site/site.toml`, above the first
  `[[nav]]` table, makes lint note each number in a page's prose that none of
  the page's linked records state. It is one setting for the whole site. Turn
  it on for a site whose pages explain Markdown records; leave it off for a
  site with pages that report measurements from experiment data, whose rounded
  or derived numbers need the project's own ledger check. With the setting on,
  the unchanged starter guide page gets a note for the sizes in its slide
  chapter; show such literal values as code.
- The sidebar groups are toned sections, the home hero has two columns, and
  numbered steps in build-sheet boxes show a number in their tone.

## Pages that explain changed guides

These kit guides changed since 2.0.0. Reread the project pages that link to
them, as the conformance check asks:

- [Documentation system](../../../../rules/documentation.md): record first and
  page on request, topic records, why pages and records overlap, record-change
  notes, the `OPEN.md` format, why the worklog repeats commit messages. Its
  sections on frozen evidence, shelved investigations and review moved out.
- [Writing records](../../../../rules/records.md): new guide; it gathers record
  format, honest claims, measured numbers, frozen evidence and shelved
  investigations.
- [Page index](../../../../rules/writing.md) and
  [site index](../../../../rules/maintenance.md): now plain indexes without
  section anchors.
- [Explanations](../../../../rules/writing/explanations.md): naming and honest
  claims moved to the records guide.
- [Figures](../../../../rules/writing/figures.md): gained run visuals and
  experiment lifecycle.
- [Delivery](../../../../rules/engineering/delivery.md): delegating a page for
  people.
- [Site authoring](../../../../rules/site/authoring.md): `brand_mark`, pinned
  source pages, the Reference section, the removed ledger paragraph.
- [Validation](../../../../rules/site/validation.md): every visual change is
  reviewed by eye from whole-element captures; local review and browser access
  moved in.
- [Publication](../../../../rules/site/publication.md): gained the publishing
  gate.
- [Reader](../../../../rules/site/reader.md): the navigation tree now ends with
  the repository files section when a site registers source pages.
- [Git](../../../../rules/engineering/git.md): the pin check counts remote
  branches only, not tags.
- [Numbers and staleness](../../../../rules/records.md#numbers-and-staleness):
  the project owns its ledger format and checks.
- [Conformance check](../../../../rules/conformance.md): new guide.

## Land the upgrade

Commit the moved pin together with the adaptations above, record the old and
new kit commits and the checks in the project's worklog, and report the
conformance findings. [Pin and upgrade](../../../../README.md#pin-and-upgrade)
has the commands, and the 1.1.0 guide's
[validate, land and retain recovery](1.1.0.md#validate-land-and-retain-recovery)
describes the landing in full.
